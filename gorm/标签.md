在 GORM 中，结构体字段后面的 `` `gorm:"..."` `` 是 **GORM 标签（Tags）**，用于告诉 GORM 如何映射这个字段到数据库表的列（column），比如：是否为主键、加索引、字段名映射、大小限制等。

你问的 `` `gorm:"index"` `` 只是其中之一。下面我们来**全面、系统地讲解 GORM 常用标签及其含义**。

---

## 🌟 一、基本语法

```go
type User struct {
    ID    uint   `gorm:"primaryKey"`
    Name  string `gorm:"size:100;index"`
    Email string `gorm:"uniqueIndex;not null"`
}
```

格式：`` gorm:"key1:value1;key2;key3:value3" ``

多个选项用分号 `;` 分隔。

---

## ✅ 二、常用 GORM 标签详解

| 标签 | 含义 | 示例 |
|------|------|------|
| `primaryKey` | 设置为主键 | `` `gorm:"primaryKey"` `` |
| `autoIncrement` | 主键自增（整型） | `` `gorm:"autoIncrement"` `` |
| `size` | 字段长度（字符串、[]byte） | `` `gorm:"size:255"` ``（默认 255） |
| `type` | 指定数据库列类型 | `` `gorm:"type:text"` ``（如 text、json、decimal） |
| `index` | 添加普通索引 | `` `gorm:"index"` `` |
| `uniqueIndex` | 添加唯一索引 | `` `gorm:"uniqueIndex"` `` |
| `column` | 指定数据库列名 | `` `gorm:"column:full_name"` `` |
| `default` | 设置默认值 | `` `gorm:"default:guest"` `` |
| `not null` | 非空约束 | `` `gorm:"not null"` `` |
| `unique` | 唯一约束（旧版，推荐用 `uniqueIndex`） | `` `gorm:"unique"` `` |
| `serializer` | 序列化方式（如 json） | `` `gorm:"serializer:json"` `` |
| `->` | 只写（数据库 → 结构体不读） | `` `gorm:"->:false"` `` 或 `` `gorm:"->"` `` |
| `<-` | 只读（结构体 → 数据库不写） | `` `gorm:"<-:create"` `` |
| `-` | 忽略该字段（不映射到表） | `` `gorm:"-"` `` |

---

## 🧩 三、详细解释每个标签

### 1️⃣ `primaryKey`：主键
```go
ID uint `gorm:"primaryKey"`
```
- 表示该字段是主键
- 可与 `autoIncrement` 连用

> ⚠️ GORM 默认会找 `ID` 字段作为主键，但显式声明更清晰。

---

### 2️⃣ `autoIncrement`：自增
```go
ID int `gorm:"primaryKey;autoIncrement"`
```
- 仅对整型有效
- 插入时数据库自动生成 ID

---

### 3️⃣ `size`：字段长度
```go
Name string `gorm:"size:100"` // VARCHAR(100)
```
- 字符串默认是 `VARCHAR(255)`
- `size:-1` 可用于 `TEXT` 或 `CLOB`

---

### 4️⃣ `type`：指定数据库类型
```go
Data string `gorm:"type:text"`        // TEXT 类型
Meta string `gorm:"type:json"`        // JSON 类型（MySQL 5.7+）
Price float64 `gorm:"type:decimal(10,2)"` // DECIMAL(10,2)
```

---

### 5️⃣ `index`：普通索引
```go
Email string `gorm:"index"`
```
- 创建一个名为 `idx_email` 的普通索引
- 提升查询性能

#### 自定义索引名：
```go
Email string `gorm:"index:idx_user_email"`
```

#### 联合索引：
```go
type User struct {
    Name  string `gorm:"index:idx_name_age"`
    Age   int    `gorm:"index:idx_name_age"`
}
```
→ 创建联合索引 `(name, age)`

---

### 6️⃣ `uniqueIndex`：唯一索引（推荐）
```go
Email string `gorm:"uniqueIndex"`
```
- 创建唯一索引，防止重复
- 比 `unique` 更灵活

#### 自定义名 + 联合唯一：
```go
type User struct {
    TenantID uint `gorm:"uniqueIndex:uix_tenant_user"`
    Email    string `gorm:"uniqueIndex:uix_tenant_user"`
}
```
→ 实现“每个租户下邮箱唯一”

---

### 7️⃣ `column`：列名映射
```go
FullName string `gorm:"column:full_name"`
```
- 结构体字段是 `FullName`，数据库列是 `full_name`
- 默认 GORM 会转为蛇形命名（`full_name`），但显式声明更清晰

---

### 8️⃣ `default`：默认值
```go
Status string `gorm:"default:active"`
Count  int    `gorm:"default:0"`
```
- 插入时如果该字段为零值，数据库使用默认值

> ⚠️ 注意：Go 的零值（如 `""`, `0`）不会触发数据库默认值，除非你用指针或 `default` 配合 `not null`

---

### 9️⃣ `not null`：非空约束
```go
Name string `gorm:"not null"`
```
- 插入时不能为空

---

### 🔟 `serializer`：序列化方式
```go
Settings map[string]interface{} `gorm:"serializer:json"`
```
- 自动将 `map`、`slice` 等序列化为 JSON 存入数据库
- 读取时自动反序列化

---

### 1️⃣1️⃣ `->` 和 `<-`：读写权限控制

| 标签 | 含义 |
|------|------|
| `` `gorm:"->"` `` | 只读（数据库 → 结构体），插入/更新时忽略 |
| `` `gorm:"<-:create"` `` | 只在创建时写入，更新时不写 |
| `` `gorm:"<-:false"` `` | 完全不可写 |
| `` `gorm:"->:false"` `` | 完全不可读 |

#### 示例：
```go
Password string `gorm:"->:false"` // 写入数据库，但从不读出来（安全）
```

---

### 1️⃣2️⃣ `-`：忽略字段
```go
TempData string `gorm:"-"`
```
- 完全不映射到数据库表
- 仅用于业务逻辑临时存储

---

## 🛠 四、实际综合示例

```go
type User struct {
    ID        uint              `gorm:"primaryKey;autoIncrement"`
    UUID      string            `gorm:"size:36;uniqueIndex;not null"`
    Name      string            `gorm:"size:100;index:idx_name"`
    Email     string            `gorm:"size:255;uniqueIndex:uix_email_tenant"`
    TenantID  uint              `gorm:"uniqueIndex:uix_email_tenant"` // 联合唯一
    Age       int               `gorm:"default:18"`
    Status    string            `gorm:"default:active;not null"`
    Meta      map[string]string `gorm:"type:json;serializer:json"`
    CreatedAt time.Time
    UpdatedAt time.Time
    DeletedAt gorm.DeletedAt    `gorm:"index"`
}
```

生成的表结构（MySQL）：
- 主键 `id`
- `uuid` 唯一索引、非空
- `name` 普通索引
- `email + tenant_id` 联合唯一
- `meta` 存为 JSON
- `deleted_at` 有索引（用于软删除）

---

## ✅ 五、小贴士

1. **标签大小写不敏感**：`index` 和 `Index` 一样
2. **默认行为**：
   - 字段名为蛇形命名（`user_name`）
   - `ID` 字段自动为主键
   - `CreatedAt`, `UpdatedAt`, `DeletedAt` 有特殊处理
3. **索引命名规则**：
   - `index:idx_xxx` → 普通索引
   - `uniqueIndex:uix_xxx` → 唯一索引
4. **使用 `gorm:"-"` 忽略不需要持久化的字段**

---

## ✅ 总结：你问的 `` `gorm:"index"` `` 是什么？

> `` `gorm:"index"` `` 表示：**为该字段创建一个普通数据库索引**，用于加快查询速度。

例如：
```go
Email string `gorm:"index"`
```
→ 在 `email` 字段上建索引，`WHERE email = ?` 查询会更快。
